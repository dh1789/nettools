## 증상부터

1TB 외장 SSD를 샀다. 연결하니 Windows 탐색기가 931GB라고 표시한다. 69GB가 사라졌다. 반품 사유가 될까 싶어 다른 PC에 꽂아도 같다. 맥에 꽂으면 1TB로 나온다.

불량이 아니다. 포맷 오버헤드도 아니다. 같은 숫자를 두 방식으로 세고 있을 뿐이다.

## 두 가지 기가바이트

디스크 제조사는 10의 거듭제곱으로 센다. 1TB = 1,000,000,000,000바이트다. 운영체제는 2의 거듭제곱으로 센다. 1TB = 1,099,511,627,776바이트(2^40)다.

라벨은 둘 다 "TB"인데 값이 다르다. 여기서 혼란이 시작된다.

IEC가 1998년에 이진 쪽 이름을 따로 정했다. KiB(키비바이트), MiB, GiB, TiB. 하지만 Windows를 비롯한 많은 소프트웨어가 여전히 이진 값을 KB·MB·GB로 표기한다.

| 단위 | SI (10진) | IEC (2진) | SI 1단위를 2진으로 |
|------|----------|-----------|-------------------|
| K | 1,000 | 1,024 | 0.977 KiB (−2.3%) |
| M | 10^6 | 2^20 = 1,048,576 | 0.954 MiB (−4.6%) |
| G | 10^9 | 2^30 = 1,073,741,824 | 0.931 GiB (−6.9%) |
| T | 10^12 | 2^40 | 0.909 TiB (−9.1%) |
| P | 10^15 | 2^50 | 0.888 PiB (−11.2%) |

**차이는 단위가 커질수록 벌어진다.** 킬로에서 2.3%였던 격차가 테라에서 9.1%가 된다. 1TB 디스크의 "사라진 69GB"가 정확히 이 값이다 — 10^12바이트를 GiB로 나누면 931.32다.

임의의 값을 두 방식으로 나란히 보려면 [바이트 단위 변환기](/tools/net/byte-unit-converter/)에 넣으면 된다. SI와 이진 결과를 동시에 보여준다.

## OS별로 다르게 센다

| 환경 | 계산 | 표기 |
|------|------|------|
| Windows 탐색기 | 2진 | "GB" (실제로는 GiB) |
| macOS 10.6+ | 10진 | "GB" (실제로 GB) |
| Linux `df -h` | 2진 | "G" |
| Linux `df -H` | 10진 | "G" |
| 디스크 제조사 | 10진 | "TB" |
| RAM 제조사 | 2진 | "GB" (실제로는 GiB) |

맥에서 1TB로 보이던 디스크가 윈도우에서 931GB가 되는 이유가 이 표에 있다. 둘 다 맞다. 세는 방식이 다를 뿐이다.

RAM이 예외인 점을 기억해두면 좋다. 메모리는 주소 체계상 2의 거듭제곱으로 만들어지므로 8GB 모듈은 실제로 8 GiB다. 스토리지와 반대다.

## 명령줄에서 확인

```bash
# 2진(1024) 기준 — G는 사실상 GiB
df -h

# 10진(1000) 기준 — 제조사 표기와 일치
df -H

# 디렉터리 크기: 2진 vs 10진
du -sh  /var/log
du -sh --si /var/log     # GNU coreutils

# 정확한 바이트 수
lsblk -b                 # Linux 블록 장치
stat -c %s file          # Linux
stat -f %z file          # macOS
```

용량 분쟁이 생기면 `-h`나 `-H` 같은 사람 친화 옵션을 버리고 바이트 원값을 본다. 원값은 하나뿐이라 다툴 여지가 없다.

Windows에서는 PowerShell로 본다.

```powershell
(Get-Item .\file.iso).Length          # 바이트
(Get-PSDrive C).Used                  # 바이트
```

## 문자와 바이트도 다르다

용량과 별개로 자주 걸리는 곳이 문자열 길이다. UTF-8에서 한글 한 글자는 3바이트, 이모지는 4바이트를 쓴다. "안녕"은 2글자지만 6바이트다.

```bash
echo -n "안녕" | wc -c   # 6 (바이트)
echo -n "안녕" | wc -m   # 2 (문자)
```

DB 컬럼을 `VARCHAR(10)`으로 잡았는데 한글 4글자에서 넘친다면 그 컬럼이 바이트 기준이라는 뜻이다. [텍스트 카운터](/tools/net/text-counter/)에 넣으면 문자 수와 바이트 수를 함께 확인할 수 있다.

## Mbps와 MB/s

네트워크는 혼동이 하나 더 겹친다. 회선 속도는 비트(bit), 파일 전송 속도는 바이트(byte)로 말한다. 8배 차이다.

| 회선 | 이론상 최대 |
|------|------------|
| 100 Mbps | 12.5 MB/s |
| 500 Mbps | 62.5 MB/s |
| 1 Gbps | 125 MB/s |
| 10 Gbps | 1,250 MB/s |

기가 인터넷을 쓰는데 다운로드가 110 MB/s쯤 나온다면 정상이다. 이론값 125에서 프로토콜 오버헤드(이더넷 프레임·IP·TCP 헤더)를 빼면 그 근처가 나온다. 1000 MB/s를 기대했다면 단위를 잘못 읽은 것이다.

소문자 b는 비트, 대문자 B는 바이트다. Mbps의 b가 소문자인 이유가 이거다.

## 코드에서 고를 때

바이트 수를 사람이 읽는 단위로 바꾸는 함수를 쓸 때, 1000과 1024 중 무엇을 쓸지 정해야 한다.

```js
// OS 표기와 맞추려면 1024
const BIN = ['B', 'KiB', 'MiB', 'GiB', 'TiB'];
// 스토리지 제조사·클라우드 청구서와 맞추려면 1000
const SI  = ['B', 'KB', 'MB', 'GB', 'TB'];

function human(bytes, base = 1024, units = BIN) {
  let i = 0;
  while (bytes >= base && i < units.length - 1) { bytes /= base; i++; }
  return `${bytes.toFixed(1)} ${units[i]}`;
}
```

기준은 이렇게 잡는다. 사용자에게 디스크 잔여 용량을 보여준다면 그 OS의 표기와 맞춘다. 청구서나 쿼터를 보여준다면 서비스 약관의 정의를 따른다. 대부분의 클라우드 사업자는 요금 계산에 SI(10^9)를 쓴다.

무엇을 쓰든 **단위 라벨을 값과 일치시키는 게 중요하다.** 1024로 나눠놓고 "GB"라고 쓰면 지금 이 글이 다루는 혼란을 하나 더 만드는 셈이다.

## 정리

- 1TB 디스크가 931GB로 보이는 건 정상이다. 10^12바이트를 GiB로 환산한 값이다.
- 격차는 단위가 커질수록 벌어진다. K에서 2.3%, T에서 9.1%.
- 스토리지는 10진, RAM은 2진, Windows 표기는 2진인데 라벨은 "GB"다.
- 분쟁이 생기면 `lsblk -b`·`stat`로 바이트 원값을 본다.
- Mbps는 비트, MB/s는 바이트다. 8로 나눈다.
- 코드에서는 1000이든 1024든 좋으니 라벨을 값과 맞춘다.
